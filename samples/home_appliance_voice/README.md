# 小家 / Home appliance voice

独立的家电语音助手**设计 sample**：以写实的客厅与开放式厨房为背景，预览三种模型选择、设备控制、意图澄清和产品手册问答。

**当前仅实现设计原型，不是可通话的语音应用。** 所有对话、设备回执和知识内容均为本地确定性脚本；不使用麦克风、浏览器 TTS、云模型、真实设备或企业文档。模型选择只改变展示方案。先确认设计，再实施真实接入。

## 本地预览

需要 Node.js 22 或更高版本，无第三方依赖。从仓库根目录运行：

```powershell
node .\samples\home_appliance_voice\preview.mjs
```

打开 <http://127.0.0.1:8092>，按 Ctrl+C 停止。端口占用时：

```powershell
$env:PORT=8093
node .\samples\home_appliance_voice\preview.mjs
```

服务仅绑定本机回环地址，只提供明确列出的静态资源，不提供仓库文件浏览。不要将这个设计服务器作为生产服务公开。

## 设计与演示路线

视觉方向：暖白、浅鼠尾草绿、原木色；真实家庭场景为主，设备状态浮层与助手面板为辅。暂用“小家”作为助手名称，没有假定客户品牌。

1. 在开始前选择 **GPT Realtime**、**GPT Live** 或 **Azure Realtime Flash**。开始模拟后锁定模型，结束后才能切换，避免暗示可以在通话中更换协议。
2. 点击“开始模拟体验”，再点“打开空调，调到 26 度”。显示模拟工具回执，空调状态更新；也可直接点击设备卡片执行开关。
3. 点击“打开电视，把灯关掉”，分别报告两项操作。勾选“模拟电视离线”后重试：电视明确失败，灯光独立执行，不报告整体成功。
4. 点击“帮我打开冰箱”，区分查看状态、接通电源、打开门。示例冰箱持续运行，不提供远程断电或电动开门；取消或改做其他操作不会执行旧请求。
5. 点击空调滤网问题，显示虚构手册的型号、章节、页码和可打开的原文。冰箱介绍展示产品问答；电视保修问题展示“资料中未找到”，不编造答案。
6. 结束后切换模型，观察音色说明；点击重置恢复全部模拟设备与会话状态，保留选定模型。

页面没有自由文本输入，避免让固定脚本看起来像真正的自然语言理解。图片是静态背景，不会随开关改变；**设备是否开启以状态标签为准**。刷新页面也会重置数据。对话、设备状态仅在内存中，不存储音频或个人信息。

### 模型与声音决策

| 方案 | 目标声音 | 当前状态 |
| --- | --- | --- |
| GPT Realtime | 轻快、温暖、清楚的中文童声风格 | 接入时验证具体部署允许的音色及端到端音频路径；尚未承诺可用 |
| GPT Live | 缺省音色，不要求童声 | 以已保存 Agent 的音色为准；不传 Realtime 音色覆盖头，不在通话中修改 |
| Azure Realtime Flash | Azure Speech HD；优先验证兼容的童声风格 | 接入时验证部署与音色；原型不调用模型 |

不模仿特定真实儿童，不需要采集儿童录音；优先使用服务提供且允许使用的合成音色。提示词能约束语气，但不能保证音色年龄。若 Realtime 没有兼容童声，应明确显示不支持并另行确认可用音色，不静默变调、不用额外 TTS 冒充端到端模型。

## 真实接入设计（尚未实现）

```text
浏览器：麦克风 / 播放 / 家庭场景 / 字幕 / 状态
    |
本 sample 的后端：鉴权、会话生命周期、模型适配
    |-- Realtime / Azure Realtime Flash：Realtime 协议 Agent
    |-- Live：独立保存的 Live Agent + delegation 后端
    |
统一业务工具：list_devices / get_device_state / control_device / search_product_manual
    |-- 模拟家庭设备（首个可通话版本仍不控制物理设备）
    |-- 企业批准的产品手册索引（按品牌、型号、版本过滤）
```

- **多模型适配**：参考相邻 [First Voice](../foundry_voice_webrtc/README.md) 的服务器鉴权、独立 Live companion、会话切换及 WebSocket/WebRTC 处理；不复制天气业务。保存后的 Agent 不能跨版本切换 `sub_protocol`，因此 Live 与 Realtime 协议使用独立 Agent，允许分属不同 Foundry 项目。切换前关闭当前会话。为避免演示时改写保存配置，真实接入建议给三个模型分别准备 Agent。
- **Flash 差异**：现有 sample 的模型 ID 为 `azure-realtime-flash-2026-10-14`，不是 `azure-realtime` 的原生 `ava` 音色路径。沿用 Azure Speech HD 配置，并验证实际部署可用性；现有 sample 会禁用 Flash 自动开场白、跳过额外启动更新、禁用自动截断，真实接入需保留这些协议差异。原型的欢迎文字只是 UI 引导，不是 Flash 自动说出的语音。
- **工具执行**：参考 [GPT Live Python tools](../gpt_live/python/README.md) 的 managed delegation / function-tool 路径，为三个模型适配相同的业务工具契约，不假定 Live 与 Realtime 的工具事件相同。真正执行必须在服务端验证设备 ID、能力、参数、授权、幂等请求 ID 和回执；当前浏览器 reducer 不是安全边界。
- **控制语义**：“打开冰箱”先澄清。冰箱持续供电，关灯/影音场景不能顺带断开冰箱；不具备电动开门能力时明确告知。设备离线、超时或部分失败时保留“未确认”，不能用模型生成的答复代替设备回执。
- **知识问答**：当前 `lookup_demo_manual` 只是精确匹配的 fixture，不是 RAG。下一阶段使用获准的 PDF/文档，按型号与版本建立索引，返回 `document_id / title / model / revision / page / excerpt`，语音简短作答、界面展示引用。手册内容仅作为资料，不得当成工具执行指令。无匹配、型号不明或服务失败时分别说明或澄清，不混用其他型号知识。
- **协议与字幕**：独立归一化音频、字幕、工具、错误与关闭事件；Live 的字幕不能标为权威保留对话历史。传输方式先沿用已验证的 sample 路径，再按网络实际情况选择。不能将支持音色选择等同于验证了端到端音频路线。
- **凭据与隐私**：Azure 凭据仅在后端，实际部署增加用户鉴权与设备授权；录音默认关闭，麦克风与录音另行征求同意。真实指标只来自实际测量，不显示伪造延迟或成本。

### 阶段与验收

| 阶段 | 交付与验收 |
| --- | --- |
| 当前：设计预览 | 家庭效果图、三模型方案、控制/澄清/失败/引用交互；本地测试与桌面/窄屏检查 |
| 设计确认后：语音接入 | 三种模型分别完成中文语音 → 工具 → 模拟状态 → 语音回复；验证实际音色、打断、结束与麦克风释放，模型切换不串会话 |
| 企业资料接入 | 使用企业授权手册；至少验证型号匹配、页码可回溯、无结果拒答、检索失败和恶意文档指令隔离 |
| 可选：真实家电 | 另行确认设备协议与授权；通过鉴权、参数限制、幂等、超时、部分失败和高风险操作确认后再启用 |

实际接入需要客户品牌/产品清单、授权手册、可用 Foundry 项目和模型部署，以及 Realtime 童声音色兼容性结果；这些不阻塞当前设计评审。

场景图由 AI 生成，无指定真实品牌、人物或客户资料。后续替换客户素材前应确认使用许可。代码与图片分别遵循仓库相应许可说明。全部示例型号和手册内容均为虚构，不适用于操作真实家电。

运行针对性测试：

```powershell
node --test .\samples\home_appliance_voice\demo.test.mjs
```

浏览器检查：开始前控制按钮禁用；开始后模型禁用；四条主脚本、离线失败、冰箱取消、无资料回答和引用弹窗正常；结束/重置清除待澄清操作；窄屏无横向溢出，键盘可操作。
